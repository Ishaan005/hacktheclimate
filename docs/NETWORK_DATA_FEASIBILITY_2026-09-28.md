# Network-aware forecast: dataset feasibility study

Checked 28 September 2026 against the [shared project vision](https://chatgpt.com/share/6aba4705-0964-83eb-b9a7-2635fa1aaafd), public source files, and this checkout. The proposed first product forecasts Irish renewable **constraints** over the next 1–24 hours, explains likely affected areas and network conditions, and lets an operator compare an intact grid with a planned-outage scenario.

## Verdict

A **planning-model prototype** is feasible with public data. We can build a static electrical network, attach prospective outages and generator locations, run approximate DC flows and selected N-1 cases, and display a national constraint-MWh forecast. We cannot yet validate a forecast of the *actual binding line, loading, or constraint group*: the repo's official half-hour labels are totals for Ireland, while public planning files are scenarios rather than live topology and measured line flows. EirGrid's own study-file disclaimer says its power-flow data are for reference and do not reflect real-time operations.

The strongest immediate experiment is a chronological **national `constraint_mwh` model** using archived, dated forecast cycles and lagged grid observations, compared with the existing non-network baseline. A network simulation can be a clearly labelled scenario layer. Location-level model outputs need a separate validation source before they become operator claims.

## Weather: two different uses

- **Historical evaluation:** [NOAA GFS public archive](https://registry.opendata.aws/noaa-gfs-bdp-pds/) is accessible without an account and NOAA permits use with attribution. We verified `.idx` objects for 24 January, 1 August and 31 August 2026. From the 24 January 00 UTC run, we downloaded the 24-hour forecast's 100 m U/V wind and six-hour mean downward shortwave radiation as three GRIB byte ranges. ecCodes decoded the valid time as **25 January 00 UTC**; the repo has a label at that exact half-hour (`constraint_mwh = 31.929`). The five Irish sample points and units are in `noaa_gfs_sample_20260124_00z_step24/irish_points_sample.csv`. This proves access and timestamp alignment for **one** historical forecast, not a complete, validated training corpus. Forecast run time is different from download time; an evaluation still needs documented publication latency and a decision-time cutoff.
- **Live regional input:** [ECMWF open IFS data](https://www.ecmwf.int/en/forecasts/datasets/open-data) has 0.25° GRIB2 forecasts under CC BY 4.0, including 100 m wind and solar radiation fields. We downloaded those three fields from the 28 September 00 UTC run at +24 h and decoded five Irish grid points; see `ecmwf_sample_20260928_00z_step24/`. The 100 m speed spans about **9.2–12.1 m/s** at these points for 29 September 00 UTC. Its public server keeps only the most recent **12 runs (about 2–3 days)**, so this is suitable for a live feed but cannot backfill the repo's Jan–Aug 2026 labels. The sampled `ssrd` is accumulated energy in J/m², not instantaneous irradiance. [ECMWF's index specification](https://confluence.ecmwf.int/spaces/DAC/pages/272310539/ECMWF+open+data+real-time+forecasts+from+IFS+and+AIFS) supports byte-range field downloads.

Neither five-point sample is a farm-level generation forecast. Regional weather must be mapped to connected capacity, converted to estimated renewable availability, and validated against out-of-sample generation. The sample GRIB files are retained under ignored `data/raw/`; the local ecCodes package used to inspect them is not an application dependency.

## Existing repo data and decisive gaps

The repo already has **99,310** Irish half-hour dispatch-down labels from 2021–August 2026 and **11,662** Jan–Aug 2026 half-hours with system context; see [data guide](DATA_GUIDE.md). The official targets separate `constraint_mwh` and `curtailment_mwh`. Their rows have no node, line, farm or constraint-group identifier. Measured same-period demand, wind generation, SNSP and interconnector flows cannot be inputs to a day-ahead forecast merely because they are in the same table.

| Proposed output | Public-data evidence now | Honest status |
| --- | --- | --- |
| National constraint probability/MWh | Official national labels plus archived weather and lagged observations | Trainable after building a real historical forecast panel and chronological holdout. |
| Outage-conditioned network scenario | TYTFS case, ratings and planned outages | Demonstrable as an approximate planning scenario after asset matching and a solver check. |
| Binding line, loading %, headroom, N-1 security | Planning case and partial seasonal ratings, no matching actual line-flow series or real topology | Scenario estimates only; cannot validate operational accuracy yet. |
| Affected WDT group / farm-level DD | Static group document and generator-node candidates, no timestamped group/farm DD labels | Explanation/hypothesis only; no supervised target or measured accuracy. |
| Voltage, inertia, reserve or RoCoF security | Policy documents and some national context | Outside the DC-flow proof; do not present as calculated security margins. |

## Practical next experiment

1. Build a **Jan–Aug 2026 NOAA GFS forecast panel** at selected Irish points, using only forecast cycles available before each decision time. Record model run, retrieval time, valid time, location and lead, and establish the publication-lag rule used in backtests. Start with wind U/V, then solar radiation and temperature. Use a bounded date/lead sample before a large backfill.
2. Train and chronologically test `constraint_mwh` against a calendar/lag-only baseline. Report the actual holdout and uncertainty, not the retrospective demo's metrics as day-ahead performance.
3. Import **one 2024 V33 TYTFS case** into a power-flow tool. Validate the case's original power balance and base flows before changing it. Resolve circuit IDs and transformers; do not splice 2026 outages or ECP ratings onto name matches without an asset crosswalk.
4. Reconcile the short-term outage summary with the annual programme, then demonstrate one named outage and one N-1 scenario. Show source vintage and match confidence in the dashboard.
5. Obtain measured line-flow/outage history or group/farm-level dispatch-down evidence before claiming that the system predicts the actual binding corridor or affected site.

The EirGrid binaries therefore remain untracked local research inputs; check redistribution and derivative-use terms before packaging them in a public submission.
